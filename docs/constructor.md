# Конструктор: дашборды, виджеты, источники

Как устройство перестаёт быть одним зашитым кадром и становится набором
экранов, которые собираются на странице настройки. По минимуму — три
дашборда, палитра виджетов, мастер источников. Не Home Assistant, а его
идея в объёме, который влезает в микроконтроллер и в голову за вечер.

## Три сущности вместо одной

Сейчас человек видит на странице настройки **коннекторы** — сущность из
устройства, а не из его жизни. Ему нечего знать про `kind: http` и путь
`Valute.USD.Value`. Он хочет «показывать курс доллара» и «лимит Claude».

Поэтому три уровня, и наружу торчит только верхний:

| Уровень | Что это | Кто видит |
|---|---|---|
| **Виджет** | «Курс BTC», «Лимиты AI», «Воздух в кабинете» — блок на экране | человек, в палитре |
| **Источник** | откуда виджет берёт данные: ключ Claude, токен HA, адрес | человек, в мастере, один раз |
| **Коннектор** | HTTP-опрос, разбор JSON, IMAP-диалог | только прошивка |

Виджет знает, какие слоты ему нужны. Источник знает, какие слоты он даёт.
Конструктор сводит их: добавил виджет «Лимиты AI» — страница сама показывает,
что для него нужен вход в Claude, и ведёт в мастер. Ничего не настроено —
виджет в палитре есть, но помечен «нужен источник».

## Дашборд

Сетка **12 колонок × 2 ряда** на теле кадра под шапкой (800×430). Виджет
занимает `span` колонок в одном ряду; ряд делит высоту по содержимому, как
сейчас (`compute_two_rows`). Три дашборда, переключение кнопками платы:
`BTN1`/`BTN2`/`BTN3` → дашборд 1/2/3. Активный запоминается в NVS —
после перезагрузки экран тот же.

Заводские дашборды:

1. **Стол** — то, что утверждено сейчас: рынки, лимиты, воздух, почта, сегодня.
2. **Дорога** — без датчиков дома: рынки, лимиты, погода, почта. Что показывать
   вне дома, где HA недоступен.
3. **Пусто** — чтобы было куда собирать своё.

Хранение: один JSON в NVS.

```jsonc
{
  "active": 0,
  "dashboards": [
    { "name": "Стол", "rows": [
        [ { "type": "markets", "span": 5 }, { "type": "limits_air", "span": 7 } ],
        [ { "type": "mail", "span": 8 },    { "type": "today", "span": 4 } ]
    ]},
    { "name": "Дорога", "rows": [ ... ] },
    { "name": "", "rows": [] }
  ]
}
```

Пустой ряд не резервирует места — второй получает всё, как сейчас.
Невидимый виджет (нет данных) не оставляет дыры — соседи по ряду делят его
`span`. Это уже работает в `compute_columns`, меняется только откуда берётся
список.

## Палитра виджетов

Базовый набор — то, что уже нарисовано и сверено с эталоном, плюс три
универсальных:

| Тип | Слоты | Мин. span | Источник |
|---|---|---|---|
| `markets` | btc, usd_rub, eur_rub | 4 | курсы (публично) |
| `limits` | limit.claude.*, limit.codex | 4 | Claude, Codex |
| `air` | co2, tvoc | 4 | Home Assistant |
| `limits_air` | оба выше, столбиком | 6 | оба |
| `mail` | mail.unread | 4 | почта |
| `today` | weather.*, calendar.* | 3 | погода (публично), HA |
| `metric` | любой один слот | 2 | любой — универсальный: «CO₂ крупно» или «курс евро» |
| `clock` | — | 2 | часы |
| `text` | — | 2 | заголовок или подпись, без данных |

Каждый виджет объявляет `requires()` — список слотов — и `draw(canvas,
store, rect)`. Это ровно то, что описано в `architecture.md` про раскладку и
что сейчас зашито прямым перечислением в `draw_frame`: перечисление
заменяется таблицей типов, дашборд — данными. Сами функции отрисовки не
меняются.

## Мастер источников

Одна страница, карточки по типу, поля — только те, которых не знает никто,
кроме владельца. Никаких `id`, `kind`, путей в JSON.

| Карточка | Что спрашивает | Что заполняет |
|---|---|---|
| **Claude** | access + refresh токены (откуда взять — написано рядом) | limit.claude.5h, .week |
| **Codex** | токен | limit.codex |
| **Почта** | адрес, пароль приложения | mail.unread |
| **Умный дом** | адрес HA, токен, затем список датчиков с выбором роли (CO₂ / TVOC / температура / своё) | co2, tvoc, … |
| **Курсы** | ничего — уже настроено | btc, usd_rub, eur_rub |
| **Погода и часовой пояс** | город, одной строкой | weather.temp, .low, .high, .summary — и часовой пояс устройства |
| **Свой JSON** | адрес, путь → слот, для тех, кому надо | что угодно |

**Город вместо координат и пояса.** Владелец вводит одну строку — «Екатеринбург»,
«Лиссабон». Устройство само:

1. Геокодит название через `geocoding-api.open-meteo.com/v1/search?name=…&count=1`
   → широта, долгота, каноническое имя. Один запрос, без ключа.
2. Запрашивает погоду по координатам с `timezone=auto` — в ответе приходит
   `utc_offset_seconds`, и это становится часовым поясом устройства. Летнее
   время учитывается само: смещение приезжает актуальное при каждом опросе.
3. Сохраняет координаты и смещение в NVS рядом с городом.

Тонкость: в режиме точки доступа у устройства нет интернета, поэтому город
сохраняется сразу, а координаты и пояс определяются при первом выходе в сеть.
Страница честно пишет «координаты определятся при подключении», а не
показывает пустоту. Пока пояс не определён — время в шапке идёт по UTC с
пометкой, а не по случайному сдвигу.

Поле «часовой пояс» с ручным числом минут из настроек уходит: оно
дублировало бы автоматику и расходилось бы с ней при переезде.

Карточка показывает состояние: «настроено · обновлено 3 мин назад» или «нет
данных с 14:20 — источник не отвечает». Это та же информация, что уже идёт в
лог коннекторов, только на странице.

Секреты после сохранения не показываются — только «задан», как сейчас у
токенов. Запись — по-прежнему только через точку доступа устройства
(`decisions.md`, п.8).

## Правила честного экрана, пришедшие с живого устройства

Каждое — замечание владельца по фотографии панели, не абстракция.

- **Лимиты показывают остаток, а не использование.** Так делает интерфейс
  Anthropic («Остаётся 46%»), и так читается вопрос «сколько у меня ещё».
  Заголовок блока говорит об этом прямо: «ЛИМИТЫ · ОСТАТОК». Рядом — время
  сброса в формате эталона.
- **График строится из истории источника, не из кеша.** Копить по точке за
  опрос и подписывать «ЗА 24 Ч» — ложь: восемь точек по пять минут это сорок
  минут. Нет истории от источника — нет графика, блок показывает только
  значение и дельту. Подпись периода берётся из того, что реально запрошено.
- **Дельта приходит от источника или считается от его же предыдущего
  значения**, а не «▲0,00%» как заглушка. Заглушка выглядит как данные.
- **`403` у Claude и Codex — это «недоступно из этой страны, нужен VPN»**, а
  не «источник не отвечает». Карточка показывает страну выхода устройства.
- **Бейджи состояния в одном стиле** (рамка), тревога — инверсией. На
  однобитной панели прозрачности нет, «без рамки» читалось как выпавшее.

## Что не делаем

- **Перетаскивание виджетов мышью.** Кнопки «вверх/вниз/шире/уже» и список
  — этого достаточно, а drag-and-drop на телефоне в captive-портале без
  внешних библиотек — отдельный проект.
- **Произвольные размеры виджетов по высоте.** Два ряда, высота по
  содержимому. Больше степеней свободы — больше способов собрать нечитаемый
  экран.
- **Виджеты с собственным кодом на устройстве.** Только базовый набор;
  универсальности хватает у `metric` и `text`.
- **Синхронизацию дашбордов между устройствами.** Устройство одно.

## Порядок работ

1. **Модель.** `Dashboard`/`Widget` в config, JSON туда-обратно, заводские три
   дашборда, тесты на разбор. Кнопки → переключение `active` с сохранением.
2. **Раскладка по данным.** `draw_frame` берёт активный дашборд, таблица
   типов → функции отрисовки. Хостовое превью рендерит все три дашборда в PNG:
   `out/dashboard-{0,1,2}.png`. Сверка эталонного «Стола» скриптом — каркас
   не должен разойтись, это регресс-тест на всю перестройку.
3. **Страница: дашборды.** Три вкладки, список виджетов, палитра, вверх/вниз,
   шире/уже, удалить. Предпросмотр — картинка с устройства
   (`GET /preview.png` рендерит активный дашборд в PNG прямо на ESP32 через
   `CanvasMemory`, он уже умеет PNG).
4. **Страница: источники.** Карточки-мастер вместо списка коннекторов.
   Состояние источника из лога опроса.
5. **Живая проверка.** Три дашборда на панели, переключение кнопками,
   сборка виджета с телефона, источник через мастер.

Каждый шаг — отдельный коммит с зелёным `verify` и превью в PNG.

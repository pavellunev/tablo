# Конструктор: дашборды, виджеты, источники

Как устройство перестаёт быть одним зашитым кадром и становится набором
экранов, которые собираются на странице настройки. Три дашборда,
переключение кнопками платы, палитра виджетов, мастер источников вместо
списка коннекторов. Не Home Assistant, а его идея в объёме, который влезает в
микроконтроллер и в голову за вечер.

Протокол самого виджета (спецификация → видимость → отрисовка → регистрация,
как добавить свой) — `docs/widgets.md`, здесь про модель дашборда и страницу.

## Три сущности вместо одной

На странице настройки человек видит **коннекторы** — сущность из устройства,
а не из его жизни: ему нечего знать про `kind: http` и путь
`Valute.USD.Value`. Он хочет «показывать курс доллара» и «лимит Claude».

Поэтому три уровня, и наружу торчит только верхний:

| Уровень | Что это | Кто видит |
|---|---|---|
| **Виджет** | «Курс BTC», «Лимиты AI», «Воздух в кабинете» — блок на экране | человек, в палитре |
| **Источник** | откуда виджет берёт данные: ключ Claude, токен HA, адрес | человек, в мастере, один раз |
| **Коннектор** | HTTP-опрос, разбор JSON, IMAP-диалог | только прошивка |

Виджет знает, какие слоты ему нужны (`widgets::Spec::slots`, для `metric` —
`Instance::slot`). Источник знает, какие слоты он даёт
(`connectors::provides`). Конструктор сводит их: добавил виджет «Лимиты AI» —
страница сама показывает, что для него нужен вход в Claude, и ведёт в мастер.
Ничего не настроено — виджет в палитре есть, но помечен «нужен источник».

## Дашборд

Не сетка колонок, а два ряда виджетов с токенами ширины — `S`/`M`/`flex`
(`docs/widgets.md`, «Протокол»): видимые с фиксированным размером берут свои
пиксели, `flex` делят остаток поровну. Токены — не произвольные числа, а
размеры блоков из утверждённого эталона (`S` = 202px, ширина «Сегодня»; `M` =
296px, ширина «Рынки»), поэтому заводской «Стол» воспроизводит его дословно.

Три дашборда, переключение кнопками платы: короткое `BTN1`/`BTN2`/`BTN3` →
дашборд 0/1/2, немедленная перерисовка (не ждёт обычный пятиминутный
интервал). Активный запоминается в `Settings.active_dashboard` — после
перезагрузки экран тот же. Долгое удержание `BTN1` (≥3 с) поднимает точку
доступа принудительно, даже если рядом есть рабочая сеть, — единственный
способ вернуться на страницу настройки без похода к роутеру.

Заводские дашборды (`config::defaults()`):

1. **Стол** — то, что утверждено сейчас: рынки, лимиты + воздух одной
   колонкой, почта, сегодня.
2. **Дорога** — без датчиков дома: рынки, лимиты (без воздуха), почта,
   сегодня. Что показывать вне дома, где Home Assistant недоступен.
3. **Свой** — пустой, чтобы было куда собирать своё.

Хранение — один JSON в NVS, компактно: `slot`/`label` только если непустые,
`divider` только если `true` (потолок NVS ≈ 8 КБ, `config.cpp::save`).

```jsonc
{
  "active_dashboard": 0,
  "dashboards": [
    { "name": "Стол", "rows": [
        [ { "type": "markets", "size": "M" }, { "type": "limits_air", "size": "flex" } ],
        [ { "type": "mail", "size": "flex" }, { "type": "today", "size": "S", "divider": true } ]
    ]},
    { "name": "Дорога", "rows": [ /* … */ ] },
    { "name": "Свой", "rows": [[], []] }
  ]
}
```

Дашбордов всегда ровно три (лишние при разборе формы отбрасываются,
недостающие — пустые), рядов — два, виджетов в ряду — не больше шести.
Неизвестный `type` (нет в реестре) отбрасывается, неизвестный `size` берёт
`default_size` виджета. Пустой ряд не резервирует места — второй получает всё,
как и раньше. Невидимый виджет (нет данных) не оставляет дыры — соседи по
ряду делят освободившееся место (`layout::layout_row`).

## Палитра виджетов

Базовый набор — восемь типов, таблица и протокол добавления своего —
`docs/widgets.md`. Кратко: `markets`, `limits`, `air`, `limits_air`, `mail`,
`today` — перенос уже нарисованного и сверенного с эталоном; `metric` и
`text` — универсальные («CO₂ крупно», «курс евро», заголовок-подпись без
данных).

`GET /api/widgets` отдаёт весь реестр (`type`, `title`, `default_size`,
`min_width`, `slots[]`, `refresh`) — палитра на странице подхватывает новый
виджет сама, без единой правки JS под конкретный тип.

## Мастер источников

Карточки по типу источника, привязанные к заводским `id` коннекторов (они
всегда есть — `merge_missing_factory_connectors` возвращает их при загрузке),
без `id`/`kind`/путей в JSON:

| Карточка | id / kind | Поля | Подсказка |
|---|---|---|---|
| Claude | `claude` / anthropic | access-токен, refresh-токен | `security find-generic-password -s "Claude Code-credentials" -w` на Mac |
| Codex | `codex` / codex | токен | `~/.codex/auth.json` → `tokens.access_token` |
| Почта | `mail` / imap | адрес IMAP, ящик, пароль приложения | Gmail: пароль приложения, не пароль аккаунта |
| Умный дом | `home` / homeassistant | адрес, токен, «не проверять сертификат», список датчиков | долгоживущий токен из профиля HA |
| Курсы | `btc`, `btc_history`, `fiat` | ничего — публичные API без ключа | только состояние |
| Погода и часовой пояс | `weather`, `geocode` + `Settings.city` | город одной строкой | координаты и часовой пояс определяются при подключении |
| Свой JSON | любые `http` не из заводского списка | id, адрес, период, токен, `map[]` | сворачиваемая секция «дополнительно» |

Состояние карточки — из `/api/status` (каждые 10 с): слот `<id>.status` с
`error` → красная строка с текстом причины; иначе по первому слоту источника
— «обновлено N мин назад» / «данных ещё нет».

Секреты после сохранения не показываются — только «задан», пустое поле
означает «оставить». Запись разрешена из любой сети, где устройство
оказалось, не только из его точки доступа (`docs/decisions.md`, п.8) — гейт
убран, вместо него `target_unchanged` в `config.cpp`: секрет не наследуется
коннектором, у которого сменился адрес или включили «не проверять
сертификат».

## Предпросмотр — на странице, не с устройства

Раньше предполагался `GET /preview.png`, рендерящий активный дашборд прямо на
ESP32. От этого отказались: устройство не должно тратить цикл рендера и
частичное обновление панели ради превью в браузере, а страница и так знает
правило ряда (`docs/widgets.md`) — способна нарисовать тот же каркас сама, на
`<canvas>` 800×480, масштабируемом по ширине: шапка полосой, виджеты
прямоугольниками с названием по тому же правилу S/M/flex, зазоры,
разделители; виджеты без настроенного источника — штриховкой. Ни одного
запроса к устройству за картинкой.

## Потребности виджетов управляют опросом

`widgets::compute_demand` (`docs/widgets.md`) считает, какие коннекторы
вообще нужны и как часто — по всем трём дашбордам сразу, не только активному:
переключение кнопкой должно показать данные сразу, а не ждать первого опроса
после смены экрана. Коннектор без единого нужного слота не опрашивается
вовсе.

## Правила честного экрана, пришедшие с живого устройства

Каждое — замечание владельца по фотографии панели, не абстракция.

- **Лимиты показывают остаток, а не использование.** Так делает интерфейс
  Anthropic («Остаётся 46%»), и так читается вопрос «сколько у меня ещё».
  Заголовок блока говорит об этом прямо: «ЛИМИТЫ · ОСТАТОК». Рядом — время
  сброса в формате эталона.
- **График строится из истории источника, не из кеша.** Копить по точке за
  опрос и подписывать «ЗА 24 Ч» — ложь: восемь точек по пять минут это сорок
  минут. Нет истории от источника — нет графика, блок показывает только
  значение и дельту. Подпись периода берётся из того, что реально запрошено.
- **Дельта приходит от источника или считается от его же предыдущего
  значения**, а не «▲0,00%» как заглушка. Заглушка выглядит как данные.
- **`403` у Claude и Codex — это «недоступно из этой страны, нужен VPN»**, а
  не «источник не отвечает». Карточка показывает страну выхода устройства.
- **Бейджи состояния в одном стиле** (рамка), тревога — инверсией. На
  однобитной панели прозрачности нет, «без рамки» читалось как выпавшее.

## Что не делаем

- **Перетаскивание виджетов мышью.** Кнопки «вверх/вниз», «в другой ряд»,
  список — этого достаточно, а drag-and-drop на телефоне в captive-портале
  без внешних библиотек — отдельный проект.
- **Произвольные размеры виджетов по высоте.** Два ряда, высота по
  содержимому. Больше степеней свободы — больше способов собрать нечитаемый
  экран.
- **Виджеты с собственным кодом на устройстве.** Только базовый набор;
  универсальности хватает у `metric` и `text`.
- **Синхронизацию дашбордов между устройствами.** Устройство одно.
- **PNG-предпросмотр с устройства.** См. «Предпросмотр» выше.

# firmware/assets — растровый шрифт Terminus

Terminus — растровый (не векторный) шрифт, у которого пиксели заданы вручную
под каждый размер, а не получены масштабированием контура. Ровно поэтому его
и выбрали (`docs/decisions.md`, п.1 и п.6): промежуточный размер векторного
шрифта на 1-битной панели рвёт штрихи — «В» превращается в «D», проверено
фотографией экрана у предшественника (`trmnl-ink`). У Terminus «промежуточных
размеров» просто не существует: есть только кегли его собственной сетки.

## Происхождение

BDF-исходники — `terminus-src/ter-u{12,14,16,20,24}n.bdf`, взяты из
официального дерева проекта Terminus Font 4.49.1
(https://sourceforge.net/projects/terminus-font/, зеркало исходников на
GitHub: `mikebeaton/terminus-font-4.49.1`). `n` в имени файла — начертание
Normal (не Bold), `u` — кодировка ISO10646/Unicode (в ней есть кириллица; без
`u` в комплекте только национальные 8-битные кодировки).

Автор — Dimitar Toshkov Zhekov. Лицензия — SIL Open Font License 1.1, полный
текст в `OFL.TXT`. Она разрешает встраивать шрифт в прошивку и распространять
дальше вместе с проектом — это здесь и происходит.

## Почему не fontconvert

Штатная утилита `Adafruit_GFX/fontconvert` конвертирует TrueType/OpenType
через FreeType — то есть растеризует контур заново. У BDF контура нет вообще,
только готовые растры: пропустить их через FreeType значило бы дать
рендерер-посредник повторно решить, куда лёг каждый пиксель, — ровно та
проблема, ради ухода от которой выбран Terminus. Поэтому здесь свой конвертер,
`convert_font.py`: BDF — текстовый формат, читается построчным парсером без
внешних зависимостей.

## Формат заголовков

`terminus_{12,14,16,20,24}.h` — сгенерированные `.h`, структуры `GFXglyph` в
них побайтово совпадают с настоящим Adafruit GFX (`bitmapOffset/width/height/
xAdvance/xOffset/yOffset`), бит в `bitmap` упакован тем же способом (сплошной
поток без выравнивания по границе строки внутри одного глифа — как у
`fontconvert`, не как в исходном BDF, который каждую строку растра дополняет
нулями до байта).

Отличие от стокового `GFXfont` — в способе адресации. Оригинал хранит один
сплошной диапазон `[first, last]` и требует записи на каждый код внутри него.
Кириллица (U+04xx) и горстка отдельных символов вёрстки (▲▼→≈°·№…) лежат от
ASCII так далеко, что сплошной диапазон означал бы многие тысячи пустых
записей ради полусотни нужных глифов. Поэтому вместо `first/last` — `codepoints[]`,
отсортированный массив кодов, параллельный массиву глифов: `fonts::find_glyph()`
ищет по нему бинарным поиском. Подробный комментарий — `firmware/src/font.h`.

## UTF-8

У стокового `Adafruit_GFX::write(uint8_t c)` в принципе нет способа принять
код выше 255 — параметр однобайтовый, а кириллица в UTF-8 всегда двухбайтовая
(да и для символов из общей пунктуации трёхбайтовая). Печать через штатный
`print()` тут не «не показывает кириллицу», а физически не может до неё
достучаться. Поэтому вместо наследования от `Adafruit_GFX` для текста —
собственная пара функций в `firmware/src/font.{h,cpp}`:

- `decode_utf8()` разбирает строку на кодовые точки сама, без библиотек;
- `draw_text()`/`text_width()` кладут пиксели через `canvas::Canvas` напрямую,
  в обход текстового движка `Adafruit_GFX` целиком.

`GxEPD2_BW` по-прежнему наследует `Adafruit_GFX` и им можно пользоваться для
отладочных ASCII-кадров (как в фазе 0, `display::show_boot_screen()`), но
вся раскладка (`layout.cpp`) текст печатает только через `fonts::draw_text()`.

## Набор символов

`convert_font.py` берёт из каждого BDF:

- `0x20–0x7E` — печатная латиница/цифры/пунктуация;
- `0x400–0x45F` — базовый блок кириллицы целиком (не по списку слов: почта и
  календарь присылают произвольный русский текст, а не фиксированный набор);
- отдельно: `° · – — ’ … ₂ № → ≈ ▲ ▼` — то, чем набрана вёрстка (разделители,
  многоточие при обрезке длинных строк, подстрочная двойка в «CO₂», стрелка
  «кадр → следующий», дельты курсов, пометка устаревшего значения).

Все перечисленные коды в шрифте Terminus существуют (проверено при генерации:
конвертер печатает число реально найденных глифов на каждый размер — сейчас
203 из 203 запрошенных на все пять кеглей). Кода, которого в BDF не нашлось,
`draw_text()` пропускает молча (без квадрата-плейсхолдера) — так решение
описано в `firmware/src/font.h`.

## Как перегенерировать

```bash
python3 firmware/assets/convert_font.py
```

Перечитывает все пять `terminus-src/*.bdf` и переписывает пять `terminus_*.h`.
Если нужен другой набор символов — правьте `ASCII_RANGE`/`CYRILLIC_RANGE`/
`EXTRA_CODEPOINTS` в начале скрипта, не сгенерированные `.h` руками.

Если нужны кегли за пределами уже скачанных пяти — Terminus существует и в
других размерах его собственной сетки (12/14/16/18/20/22/24/28/32), но
**не в промежуточных**: правило «кегли только из сетки шрифта»
(`docs/decisions.md`, п.6) держит и здесь. Исходники — тот же репозиторий,
что и для уже скачанных пяти.
